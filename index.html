Real-Time Crowd Management System

Computer vision analytics for spatial density estimation and crowd tracking.

Problem Statement

Manual crowd monitoring in public spaces is inefficient and inconsistent. Security operators struggle to continuously gauge crowd density across multiple feeds, making it difficult to preemptively identify overcrowded areas and respond effectively.

Key Features

  • Person Detection & Tracking: Utilizes pretrained YOLOv8 for accurate human detection paired with centroid-based tracking to maintain approximate object identities across frames.
  • Grid-Based Density Estimation: Divides monitored scenes into spatial grids to estimate regional concentration dynamically.
  • Dashboard Analytics: Presents live visual analytics, historical trends, and density metrics.

Technical Architecture

Incoming video frames and submitted field images are processed through OpenCV. A core engineering decision was to implement frame skipping, selectively bypassing frames to drastically reduce computational workload and improve processing throughput on constrained hardware without sacrificing critical tracking fidelity. Raw detections are subsequently aggregated by a Node.js/Express backend (backed by MongoDB) into hourly and daily rollups.

Engineering Challenges

  • Balancing the computational cost of continuous object detection with the need for high temporal resolution using adaptive frame skipping.
  • Addressing occlusion, variable lighting, and tracking failures inherent to simple centroid-based association in extremely dense crowds.

Limitations & Future Improvements

Currently, the centroid-based tracking mechanism may drop or swap identities when individuals overlap heavily or briefly exit the frame. Future iterations will focus on integrating more robust multi-object tracking (e.g., DeepSORT) to handle heavy occlusion, implementing localized density alerts, and testing performance under edge-device resolution constraints.

TradeX — Online Trading Exchange Simulator

A full-stack algorithmic simulation of an order-matching trading environment.

Problem Statement

Financial trading interfaces must reliably organize volatile buy and sell orders while strictly applying algorithmic rules for execution. This educational simulator explores the core concepts of exchange architecture by implementing a deterministic matching engine and reflecting order states in real-time.

Key Features

  • Order Management: Users submit targeted buy/sell orders that traverse lifecycle states (pending, partially filled, filled).
  • Matching Engine: Implements a strict price-time priority algorithm to pair buyers and sellers.
  • Portfolio Accounting: Simulates holding balances and tracks executed transaction histories.

Technical Architecture

The core of the system is a custom C++ matching engine built around Standard Template Library (STL) data structures for rapid order-book management. It executes partial and full fills based on price-time priority—better-priced orders execute first, and ties are broken by arrival time. The engine is cleanly decoupled from the frontend, communicating state changes to a Node.js/Express application which manages authentication, user portfolios, and the React dashboard visualization.

Engineering Challenges

  • Maintaining exact order-matching sequences and state consistency during partial executions.
  • Separating the high-performance algorithmic execution logic from the user-facing dashboard components.

Limitations & Future Improvements

TradeX is designed exclusively as an educational simulator and lacks production-grade financial security, concurrency guarantees, and persistent database clustering. Future improvements include expanding order types (e.g., market and stop-limit orders), automated edge-case benchmarking under high synthetic volume, and enhanced execution-history graphs.

WeatherNow — Weather Forecast Application

Responsive, lightweight weather dashboard integrating third-party APIs and browser geolocation.

Problem Statement

Users often require instantaneous weather retrieval for their current location or a specific city without navigating dense, ad-heavy commercial weather platforms. WeatherNow aims to provide a frictionless, immediate weather search experience.

Key Features

  • Geolocation & Search: Retrieves weather by manually searching a city name or utilizing browser GPS coordinates.
  • Detailed Conditions: Displays temperature, feels-like metrics, humidity, wind speed, pressure, visibility, daily high/lows, and sunrise/sunset times.
  • Caching & UX: Supports on-the-fly Celsius/Fahrenheit toggling and persists up to five recent city searches using localStorage.

Technical Architecture & Security

WeatherNow is constructed purely with HTML, CSS, and Vanilla JavaScript. It interfaces asynchronously with the OpenWeather API via standard fetch() requests. The DOM is updated dynamically to reflect loading states, dynamic weather icons, and error handling for invalid queries.

Security Note: Currently, the OpenWeather API key is utilized directly in frontend JavaScript. Because browser-delivered code inherently exposes such keys, it is strictly recommended to apply HTTP referer (domain) restrictions in the API provider dashboard to prevent unauthorized quota consumption.

Engineering Challenges

  • Managing asynchronous network responses gracefully, providing accurate user feedback during latency or 404 Not Found (invalid city) errors.
  • Handling edge cases where users deny browser Geolocation permissions.

Limitations & Future Improvements

The application only surfaces current weather parameters provided by the API; it does not predict future severe weather events. Future iterations should proxy API requests through a backend serverless function to completely hide the API key, add hourly forecasting modules, and include request cancellation for rapidly overlapping searches.

Smart Agriculture Decision Support System

Machine learning prediction pipeline evaluating soil and weather for crop viability.

Problem Statement

Crop selection heavily depends on granular environmental data, including soil nutrients (N, P, K), pH, humidity, and rainfall. Making agricultural decisions without evaluating these factors limits yield potential. This project provides an interface that applies machine learning to current metrics to recommend optimal crops.

Key Features

  • Crop Recommendation: Leverages a trained classifier over 22 distinct crop categories.
  • Weather Integration: Automatically retrieves live environmental context (temperature, humidity) via the OpenWeather API based on user location inputs.
  • Explainability & Context: Utilizes SHAP to interpret model decisions alongside a LangGraph/RAG pipeline for domain-specific knowledge retrieval.

Technical Implementation & Evaluation

The core pipeline cleans agricultural datasets and trains a classification model using Scikit-learn. The model achieved a reported 99.55% test accuracy (438/440 correct predictions) and a 99.38% cross-validation accuracy on the training dataset. The saved model is served via a Flask backend that seamlessly integrates OpenWeather API payloads to fulfill prediction prerequisites dynamically.

Engineering Challenges

  • Ensuring strict parity between training-stage data preprocessing and real-time inference inputs.
  • Handling external API failures gracefully to avoid breaking the inference pipeline.

Limitations & Future Improvements

Dataset performance does not guarantee success across unrepresented geographic regions or anomalous growing seasons. The system should not replace local agronomist expertise. Future improvements will focus on validating the model on independent, region-specific datasets, providing predictive uncertainty scores, and expanding fallback handling for API timeouts.

Attendance Tracking System

Client-side application for maintaining records and threshold monitoring.

Problem Statement

Manually maintaining academic attendance complicates the ongoing calculation of subject-wise percentages, making it difficult for students to monitor if they are meeting strict 75% institutional attendance requirements.

Key Features

  • Subject & Threshold Monitoring: Dynamically calculates attended vs. total classes to immediately flag subjects falling below a 75% threshold.
  • Record Management: Features calendar-based history viewing, data import/export capabilities, and an undo function for recent actions.
  • Browser Storage: Utilizes localStorage for lightweight, immediate persistence without requiring account creation.

Technical Architecture

The application relies heavily on DOM manipulation and JavaScript-based state management. When an attendance event is marked, the core logic recalculates the fractional percentage and selectively updates the UI dashboard. Data is serialized into JSON and stored persistently via the browser's native localStorage API, enabling rapid session recovery.

Engineering Challenges

  • Implementing a reliable undo stack without corrupting the overall attendance state.
  • Structuring the import/export JSON schema to ensure data integrity during backups and restorations.

Limitations & Future Improvements

Because the app relies on localStorage, data is inextricably tied to the specific browser and device, risking permanent loss if browser cache is cleared. It is currently a single-user local tool. Future improvements include implementing an optional backend (Node.js/MongoDB) for cloud synchronization, user authentication, and generating exportable PDF attendance reports.
